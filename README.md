# Sprint Map

**Посмотрите, как зависимости задач и занятость команды влияют на срок проекта.**

Sprint Map — локальное веб-приложение для планирования небольшой команды.
Оно распределяет часы по доступности участников, показывает ожидание зависимостей
и позволяет сравнить исходный план со сценарием изменений.

Local-first team planning with resource capacity, task dependencies and explainable
what-if scenarios. Russian interface. No account, API key or runtime dependency.

## Запуск

Нужен Node.js 24 или новее. Установка пакетов для запуска не требуется.

```sh
npm start
```

Откройте **http://127.0.0.1:4174**. Если порт занят: `npm start -- 4175`.
Сервер доступен только на этом компьютере. Открытие HTML через `file://`
не поддерживается: JavaScript-модулям нужен HTTP-сервер.

## Демонстрация за минуту

Первый запуск открывает вымышленный план «Прототип к демодню»: 3 участника,
8 задач, 74 часа работы. Дедлайн — конец рабочего дня 7, завершение — день 8.

1. Нажмите «Сборка интерфейса» на временной шкале. Задача ждёт завершения
   экранов, затем ещё один день — доступности Дана, занятого расчётным модулем.
2. Нажмите «Создать сценарий». Исходный план фиксируется для сравнения.
3. В списке задач измените «Сборка интерфейса»: назначьте Миру вместо Дана.
4. Завершение сдвинется с дня **8 на день 7**: проверка начнётся на день раньше.
   Исходные оценки и дедлайн при этом не меняются. Предполагается, что Мира
   умеет выполнять эту задачу; навыки приложение автоматически не проверяет.
5. Переключитесь на «Исходный план», затем обратно на «Сценарий».
6. Для дополнительной задачи выберите «Убрать объём». Перед удалением виден
   список всех зависимых задач. Обязательные задачи защищены от такого сокращения.
7. Экспортируйте JSON и импортируйте его обратно: оба плана сохраняются вместе.

Удаление дополнительной задачи не обязательно сокращает срок: результат зависит
от зависимостей и загрузки конкретного исполнителя.

## Что можно делать

- Создавать свой план с названием и дедлайном.
- Добавлять участников, их дневную доступность и недоступные рабочие дни.
- Создавать задачи с оценкой, исполнителем, зависимостями и днём доступности.
- Отмечать обязательные и дополнительные задачи.
- Смотреть распределение часов и причины ожидания задачи.
- Сравнивать исходный план со сценарием переназначений и изменения оценок.
- Сокращать дополнительный объём с учётом всех зависимых задач.
- Сохранять изменения в браузере, экспортировать и импортировать JSON.

## Как считается расписание

Дни — условные **рабочие дни**, пронумерованные от 1. Дедлайн — конец указанного
дня. Календарные даты, праздники и выходные не вычисляются.

Задачи рассматриваются в порядке списка. Перед каждой задачей размещаются её
предшественники. Часы распределяются по первым свободным дням назначенного
исполнителя. Зависимая задача может начинаться только со следующего рабочего дня
после завершения всех предшественников, даже если у человека остались часы сегодня.

Независимые задачи могут делить дневную доступность человека. Сумма распределённых
часов за день её не превышает. Задача может прерываться недоступными днями и ранее
размещённой работой. Приложение не назначает точное время суток.

Это детерминированная эвристика: она строит выполнимый вариант в рамках заданных
правил, **не гарантирует кратчайшее расписание**. Результат зависит от порядка
списка, оценок и корректности зависимостей. Это не AI-прогноз.

В блоке нагрузки показаны все назначенные часы и доступность участника до дедлайна.
Если первые больше вторых, часов точно не хватает. Обратное не гарантирует
своевременного завершения: мешать могут зависимости и поздняя доступность задач.
Объяснение ожидания относится к первому дню старта, а не ко всем паузам в работе.

## Ограничения первой версии

- До 10 участников и 40 задач; одна задача — один исполнитель.
- Доступность: 1–12 целых часов в день. Оценка: 1–80 целых часов на задачу.
- Дедлайн, день доступности и недоступные дни: от 1 до 90.
- Горизонт расчёта: 366 рабочих дней; превышение даёт ошибку.
- Нет автоматического назначения по навыкам, подбора оптимального состава
  первой версии, совместного редактирования, регистрации и внешних интеграций.
- Дополнительный объём выбирает пользователь; приложение проверяет последствия.
- В интерфейсе один сценарий; его сброс возвращает исходный план.
- Длина названий до 100 символов. JSON до 200 000 символов.

## Данные и конфиденциальность

Данные хранятся в localStorage этого браузера на текущем адресе. Очистка данных
сайта или переход на другой порт может сделать сохранение недоступным. Экспорт
JSON — переносимая резервная копия; он включает названия, имена и оба плана.
Проверяйте его содержимое перед передачей кому-либо.

Файлы проекта не загружаются на сервер. Нет аналитики, CDN, внешних шрифтов
или внешнего AI-сервиса. Если браузер запрещает сохранение, приложение сообщает
об этом; сохраняйте работу через экспорт. Повреждённое сохранение при старте
не затирается демонстрационными данными автоматически.

## Разработка и проверки

```sh
npm ci --ignore-scripts
npm run check
```

Проверки: ESLint, Prettier, тесты Node.js. Зависимости npm нужны только разработке.
DOM-тесты используют LinkeDOM; они не заменяют проверку интерфейса в браузере.

```text
src/planner.js       Валидация, расписание, сравнение, последствия удаления
src/storage.js       Проверяемый импорт/экспорт и локальное хранение
src/demo.js          Вымышленный демонстрационный проект
src/app.js           Формы, временная шкала и пользовательские действия
src/main.js          Запуск приложения
scripts/serve.js     Локальный сервер с белым списком публичных файлов
tests/              Расчёты, ограничения, хранение, DOM и HTTP
docs/design.md      Правила первой версии и интерфейсы модулей
```

Сборка не нужна. Для статического размещения нужны `index.html`, `styles.css`,
`favicon.svg`, папки `src/` и `assets/`. Размещение в интернете выполняется отдельно.

## Оформление и шрифт

Montserrat загружается локально из `assets/fonts/`. Шрифт распространяется
по [SIL Open Font License](assets/fonts/OFL.txt); его лицензия отличается от
лицензии кода. Оформление в духе Liquid Glass использует CSS-прозрачность,
размытие и светлую кромку. Для повышенного контраста, уменьшения прозрачности
и браузеров без backdrop-filter предусмотрены плотные поверхности.
