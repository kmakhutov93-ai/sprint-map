# Sprint Map — первая версия

Согласованный проект: команда, зависимости задач, доступность людей,
дедлайн, сценарии изменений и сокращение дополнительного объёма. Только локальная
разработка, без аккаунтов, внешних сервисов и production-зависимостей.

## Правила

Рабочие дни пронумерованы от 1, без календарных дат и выходных. Участник имеет
целую дневную доступность 1–12 часов и список недоступных рабочих дней.
У задачи один исполнитель, оценка 1–80 целых часов, день доступности 1–90,
список предшественников и признак обязательности. До 10 участников, 40 задач.
Дедлайн 1–90 рабочих дней. Названия непустые, до 100 символов.

Расчёт детерминированный: готовые к размещению задачи выбираются в порядке
списка, сначала размещаются их предшественники. Затем часы распределяются по
первым свободным дневным ёмкостям исполнителя. Зависимая задача начинается
не раньше следующего рабочего дня после завершения всех предшественников.
Несколько независимых задач могут делить дневную доступность человека.
Расчёт не определяет точное время суток и не доказывает оптимальность расписания.
Горизонт поиска — 366 рабочих дней; превышение даёт явную ошибку.

Часы не дублируются, ёмкость человека не превышается. Циклы, неизвестные ссылки,
повторяющиеся ID, некорректные числа и форматы отвергаются до расчёта.
Нет притворного AI, прогнозов и автоматических назначений исполнителей.

## Модель и интерфейсы модулей

Project = {version:1, name, deadline, people:[{id,name,capacity,away:number[]}],
tasks:[{id,title,personId,hours,dependencies:string[],required:boolean,releaseDay}]}.
Идентификаторы /^[a-zA-Z0-9_-]{1,40}$/; внутри каждой коллекции уникальны.

`validateProject(input)` возвращает нормализованную глубокую копию или бросает Error.
`schedule(project)` возвращает {finishDay,totalHours,lateDays,tasks,loads}.
tasks: [{id,startDay,endDay,allocations:[{day,hours}],dependencyReadyDay,
resourceDelayDays,blockingDependencies:string[],waitingFor:string[]}].
loads: [{personId,hours,availableBeforeDeadline,overByHours,days:[{day,hours}]}].
resourceDelayDays — календарная разница рабочих индексов между допустимым днём
старта по зависимостям/releaseDay и фактическим стартом, включая отсутствие человека.
waitingFor — ранее размещённые задачи, занявшие ёмкость в этот период ожидания.
`comparePlans(base,scenario)` возвращает {base,scenario,finishDelta,changes},
changes: [{id,beforeEnd:number|null,afterEnd:number|null,delta:number|null}].
`removalImpact(project,id)` возвращает {removedIds,blockedByRequired:string[]}:
выбранная задача и все её транзитивные зависимые. Удалять набор нельзя, если
в нём есть обязательная задача. `removeOptional(project,id)` валидирует это и
возвращает копию. Обычное удаление задачи с зависимыми запрещено в редакторе.

Workspace = {version:1,base:Project,scenario:Project|null}.
`parseWorkspace(text)`, `serializeWorkspace(workspace)`, `loadWorkspace(storage)`,
`saveWorkspace(storage,workspace)` в src/storage.js. Лимит JSON 200 000 символов.
loadWorkspace возвращает null при отсутствии сохранения, ошибки не скрываются.
localStorage key sprint-map.workspace.v1. Импорт проверяет обе модели до замены.
Нельзя затирать повреждённое сохранение при старте; пользователь получает ошибку.

## Пользовательский поток

Первый запуск показывает вымышленный демонстрационный план. Можно создавать,
редактировать и удалять участников и задачи; заполненные формы проверяются.
Удаление используемого участника отвергается. Зависимости выбираются из списка.
Исходный план редактируется до создания сценария. Кнопка создания сценария
фиксирует исходный план и копирует его; все дальнейшие изменения касаются сценария.
При сравнении можно просматривать исходный план, он только для чтения.
Сброс сценария возвращает к исходному; перед потерей сценария нужно подтверждение.
Импорт и загрузка демо также требуют подтверждения, когда заменяют текущую работу.

Сводка показывает рабочий день завершения, отклонение от дедлайна, общий объём,
изменение относительно исходного плана. График содержит строки задач, дневные
распределения часов и отметку дедлайна; рядом команда и нагрузка до дедлайна.
Выбор задачи открывает объяснение зависимостей и ожидания ресурса. Дополнительную
задачу можно убрать из сценария после просмотра полного списка зависимых.
Если затронута обязательная задача, операция блокируется с объяснением.

## Дизайн

По запросу пользователя: Montserrat и веб-оформление в духе Liquid Glass.
Фон #edf3fa, текст #1e304a, синий #1767ce, туман #dceafa, коралловый #a63d48,
белый #ffffff. Локальный вариативный Montserrat, включая кириллицу; компактные
подписи, крупный заголовок проекта, табличные цифры в сводке и графике.
Слева команда, справа график, ниже редактирование и сравнение. Панель управления
полупрозрачная, кнопки в форме капсул; карточки со светлой кромкой и мягкой тенью.
График расположен на плотной светлой поверхности для читаемости данных.
Эффект стекла реализован средствами CSS, без нативных Apple API.
Без поддержки backdrop-filter используются непрозрачные поверхности;
prefers-reduced-transparency и prefers-contrast уменьшают прозрачность и декор.
Мобильный экран: блоки в столбец, горизонтальный скролл только внутри графика.
Кнопки 44px, клавиатурный фокус, текстовые подписи и reduced-motion.

## Проверки

Ручные эталоны расписаний, циклы, ограничения ёмкости, отсутствие человека,
границы дней, сравнение без мутаций, замыкание зависимых при сокращении объёма,
строгий импорт и ошибки хранения. DOM-тесты основных действий и XSS-текста.
HTTP-сервер разрешает только публичные файлы. Визуальная проверка при доступном браузере.
